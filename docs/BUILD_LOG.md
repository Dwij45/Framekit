### 0.8 Postgres port collision (important)

```powershell
npm run migrate -w @framekit/db -- --name phase0_users
```

**Failed:** Prisma `P1000` authentication failed.

`docker exec framekit-postgres-1 psql -U framekit ...` **worked**. So the
container password was correct.

```powershell
netstat -ano | findstr ":5432"
tasklist /FI "PID eq 8900"
```

**Two listeners on 5432:**

- `postgres.exe` (PID 8900) — a **Windows** Postgres already on the machine
- `com.docker.backend.exe` — Docker’s published port

Prisma on the host talked to the Windows service, not Framekit’s container.

**Fix:** publish Docker Postgres on **5433** instead:

```yaml
ports:
  - "5433:5432"
```

`5433` on your PC → `5432` inside the container.

```powershell
docker compose -f infra/docker-compose.yml up -d postgres
```

`DATABASE_URL=postgresql://framekit:framekit@127.0.0.1:5433/framekit`

Also used `127.0.0.1` instead of `localhost` because on Windows `localhost`
often goes to IPv6 (`::1`) first.

**Retry:**

```powershell
npm run migrate -w @framekit/db -- --name phase0_users
```

**Result:** applied `packages/db/prisma/migrations/20260817125850_phase0_users/`
and created table `"User"`.

**What you learned:** “I have Docker Postgres” is not enough. Check **which
process owns the port**. This is a classic production footgun.

### 0.9 Auth + dashboard (what we coded)

| Piece | Where | Why |
| --- | --- | --- |
| Auth.js Credentials + JWT | `apps/web/auth.ts` | Email/password for the dashboard. JWT so middleware can run on the Edge **without** Prisma. |
| `authorize()` uses Prisma + bcrypt | same file | Password check happens on Node during `signIn`, not in middleware. |
| Route Handlers | `app/api/auth/[...nextauth]/route.ts` | Auth.js HTTP endpoints (`/api/auth/signin`, session, csrf). |
| Register | `app/api/register/route.ts` | **Route Handler**, not a Server Action, so we can `curl` it. bcrypt cost 12. |
| Middleware | `apps/web/middleware.ts` | Protects `/`, `/assets`, `/jobs`, `/api-keys`, `/docs`. Does **not** protect `/login` or `/api/health`. |
| Health | `app/api/health/route.ts` | `SELECT 1` on Postgres, `PING` Redis, `GET /minio/health/live`. |
| Dashboard shell | `app/(dashboard)/*` | Route **group** `(dashboard)` does not appear in the URL. Layout adds the sidebar. |
| `"use client"` forms | `components/login-form.tsx` etc. | `signIn()` and `useState` need the browser. Pages stay Server Components. |

**Why bcrypt, not plaintext:** if the DB leaks, hashes are not reversible
(with a proper cost factor).

**Why JWT, not database sessions for v0:** middleware would otherwise need
Prisma on the Edge, which we do not want.

### 1BCD.1 What shipped

| Piece | Where | Why |
| --- | --- | --- |
| `Rendition` table | `packages/db/prisma/schema.prisma` | Metadata for MP4s / HLS master / poster. Segments stay in MinIO only. |

| Retry | `POST /api/v1/jobs/[jobId]/retry` | Failed jobs, and 1A probe-only `ready` jobs with no renditions. New BullMQ id so we do not collide with a completed queue job. |

### 1BCD.2 Failures we hit while wiring this

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'ffmpeg-static'
```

`package.json` listed it before `npm install` finished. After install, the worker logged:

`[worker] Phase 1B–1D — listening on queue ingest (probe + encode + HLS).`

Then a real ingest (`cmsxdpfqj0003ckd8e4dsnfli`) died:

```
Timed out fetching a new connection from the connection pool
Can't reach database server at `127.0.0.1:5433`
```

**Why:** FFmpeg stderr was firing `prisma.job.update` faster than the pool could recycle (`void setJob(...)` overlapped). Then Docker/Postgres on **5433** became unreachable (engine not responding to `docker version` / `docker compose ps`).

**Fix in code:** only one in-flight progress write at a time; BullMQ `lockDuration` 15 minutes.

**Fix in runtime (2026-08-17, later the same day):** Docker Desktop was killed because it hung the PC. We did **not** wait on Compose. Native stand-ins:

- Private Postgres cluster on **5434** via already-installed PostgreSQL 18 `initdb`/`pg_ctl` (Windows service on **5432** untouched)
- Portable Redis 7 + MinIO exes under `%LOCALAPPDATA%\framekit`
- Worker still uses `ffmpeg-static` (no host FFmpeg)

```powershell
npm run infra:local
npm run dev
npm run dev:worker
```

Stop: `npm run infra:local:stop`. Later Docker: `npm run infra:up` and `DATABASE_URL` port **5433**.
